# 곡 추가하기 (음원 라이브러리)

실습 음원은 곡 단위로 관리한다. 곡 하나 = 소스 파일 묶음(`public/audio/songs/<곡 id>/`) + 매니페스트 하나(`src/audio/library/songs/<곡 id>.ts`). 음악을 만드는 기능이 아니라, 실습마다 어떤 곡의 어떤 소스로 연습할지 고르는 데 쓴다.

## 1. 조건부터 확인한다

- 저작권과 이용 조건이 확인된 멀티트랙만 쓴다. 조건 원문 주소와 확인 날짜를 매니페스트 `terms`에 적는다.
- 공개 웹에서 들려줘도 되는지가 불확실하면 `terms.caution`에 적고, 프로덕션 배포 전에 사용자에게 확인받는다.

## 2. 구간과 묶음을 정한다

`tools/songs/<곡 id>.json`을 만든다.

| 키 | 뜻 |
|---|---|
| `bpm`, `beatPhaseSec` | 템포와 첫 박의 위치(초). 킥 트랙의 시작점들로 찾는다 |
| `startBeat`, `beats` | 몇 번째 박부터 몇 박을 자를지. 마디(4박) 단위로 잘라야 루프가 매끄럽다. 모든 소스가 고르게 나오는 구간(합창 등)을 고른다 |
| `groups` | 소스 키 → 더할 원본 트랙 이름들(확장자 없이). 백킹 보컬 8개처럼 여러 트랙을 하나로 묶는다 |
| `reference`, `referenceOffsetSec` | 원곡 완성 믹스 파일과, 스템보다 몇 초 앞서 있는지(음수면 앞섬). 엔벨로프 상관으로 잰다 |

## 3. 파일을 만든다

```bash
python3 tools/make-song.py tools/songs/<곡 id>.json <원본 WAV 폴더> <원곡 믹스 폴더>
```

macOS `afconvert`와 파이썬 표준 라이브러리만 쓴다. 소스마다 피크·RMS가 출력된다.

## 4. 매니페스트를 쓴다

`src/audio/library/songs/actions-devils-words.ts`를 본떠 만들고 `src/audio/library/index.ts`의 `SONGS`에 넣는다.

- `stems`: 키, 이름, **역할**(킥·스네어·탐·오버헤드·퍼커션·베이스·기타·건반·리드 보컬·백킹 보컬·말소리), 파일, 출력된 피크·RMS, 묶은 원본
- `mixer`: 쉬운 믹서 8채널에 꽂을 소스와 기본 페이더·모니터 보내는 양
- 미션은 역할로 채널을 찾는다. 리드 보컬, 기타, 스네어, 백킹 보컬, 베이스가 채널 배치에 있어야 미션 4종이 모두 열린다(없는 미션은 숨겨진다)

## 5. 출처를 적는다

- 출처 페이지(`/credits/`)는 매니페스트에서 자동으로 만든다.
- `public/audio/SOURCES.md`에도 같은 내용을 적는다.

## 6. 검사

`npm test`가 매니페스트(파일 경로, 채널 8개, 출처, 미션 역할)와 실제 파일 디코딩·길이를 검사한다. 레슨 파일처럼 새 파일이 생기면 `vercel deploy --prod --force`로 배포한다.
