# 음향 시스템 랩 서비스 기획서 (PRD)

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-10-20 |
| 상태 | 초안 |
| 근거 | 2026-10-20 기획 인터뷰(21개 결정, 맨 끝 「결정 기록」) |
| 관련 문서 | 개발 스펙 yoochangyeon/sound-system-lab#1, 작업 규칙 `CLAUDE.md` |

이 문서는 무엇을, 누구에게, 어떤 화면으로 제공하는지를 정한다. 구현 방식(모듈, 테스트)은 개발 스펙에서 정한다. 둘이 다르면 이 문서를 먼저 고치고 스펙을 맞춘다.

---

## 1. 개요

### 한 줄 정의

교회 방송실 봉사자가 디지털 믹서의 처리 기능을 브라우저에서 직접 만지고 들으며 배우는 무료 학습 사이트.

### 배경

- 교회 방송실 봉사자 대부분은 음향을 전공하지 않았다.
- 예배 중에 하울링이 나거나, 설교가 웅웅거리거나, 어떤 채널에서 소리가 안 나도 무엇을 만져야 하는지 모른다.
- 기존 자료는 이론 위주이거나 영어 매뉴얼이다.
- 실제 콘솔은 예배 시간에만 만질 수 있어서 소리를 바꿔 보며 연습할 기회가 거의 없다.

### 목표

1. 봉사자가 주일 예배에서 자주 생기는 문제를 보고 어느 구역의 어떤 노브를 만져야 하는지 안다.
2. 처리기(EQ, 컴프레서, 게이트 등)가 소리를 어떻게 바꾸는지 귀로 구분한다.
3. 실제 콘솔 앞에서 당황하지 않도록 X32·dLive와 비슷한 화면 구조를 미리 익힌다.

### 서비스 원칙

| 원칙 | 뜻 |
|---|---|
| 완전 무료 | 로그인, 진도 저장, 결제를 만들지 않는다 |
| 현장 상황에서 시작 | 이론보다 "이 소리가 나면 무엇을 만지나"를 먼저 다룬다 |
| 듣고 만지며 배운다 | 설명마다 바로 만져 볼 수 있는 위젯을 붙인다 |
| 용어는 바로 풀이 | 용어가 처음 나오면 한 줄로 풀어 쓴다 |
| 자체 디자인 | 실제 기기 화면이나 로고를 베끼지 않고, 레이아웃과 조작 흐름만 본뜬다 |

## 2. 대상 사용자

### 주 대상: 교회 방송실 봉사자

| 항목 | 내용 |
|---|---|
| 배경 | 음향 비전공. 주일마다 방송실에서 콘솔을 만진다 |
| 아는 것 | 페이더 올리고 내리기, 뮤트 정도 |
| 모르는 것 | 게인 스테이징, EQ 주파수, 컴프레서·게이트 파라미터, Aux 모니터 믹스, 패치 |
| 자주 겪는 문제 | 하울링, 웅웅거리는 설교 목소리, 들쭉날쭉한 보컬 크기, 소리 안 나는 채널, 모니터가 안 들린다는 요청 |
| 쓰는 기기 | 레슨은 휴대폰(이동 중, 방송실), 실습은 태블릿 가로·노트북 |
| 쓰는 콘솔 | X32 계열 또는 dLive 계열 |

### 대상이 아닌 사람

- 음향 전공자, 레코딩 엔지니어(믹싱·마스터링 심화는 다루지 않는다)
- 특정 기기의 모든 메뉴를 배우려는 사람(매뉴얼을 대신하지 않는다)

## 3. 1차 범위

1차 범위를 전부 완성한 뒤 한 번에 공개한다.

### 포함

| 영역 | 내용 |
|---|---|
| 1장 기초 | 레슨 5편: 신호 흐름, dB·게인 스테이징, 주파수와 대역, 마이크 종류·지향성, 스피커·모니터 배치 |
| 2장 처리기 | 레슨 5편 + 위젯 5종: 프리엠프, PEQ+HPF, GEQ 31밴드(하울링 데모), 컴프레서, 게이트 |
| 3장 콘솔 | 콘솔 화면 둘러보기 레슨 + 실습실(X32 스타일, dLive 스타일) |
| 미션 | 4종: 하울링 잡기, 설교 또렷하게, 게인 맞추기, 소리 안 나는 채널 |
| 기타 | 음원 출처 페이지, 공개 전 '준비 중' 페이지 |

### 제외

| 제외 항목 | 이유 |
|---|---|
| 로그인, 진도·미션 완료 저장, 결제 | 완전 무료, 가입 없는 서비스 |
| 방문 통계, 피드백 창구 | 인터뷰에서 넣지 않기로 함 |
| 마이크 입력, 사용자 음원 파일 열기 | 권한 요청과 하울링 위험. 모두 같은 음원으로 배운다 |
| 귀 훈련 퀴즈, 정답 바로 적용 버튼 | 단계 힌트와 해설로 대신한다 |
| 씬 저장/불러오기, 모니터 요청 처리 미션 | 1차 화면 범위에서 뺌 |
| 디에서·리미터·익스팬더 위젯, 사이드체인 | 1차 처리기 범위에서 뺌 |
| 기종별 고유 동작(레이어·뱅크, 기종별 처리 차이) | 엔진과 미션은 공유하고 화면만 다르게 만든다 |
| 휴대폰 세로 화면용 콘솔 | 콘솔은 가로 태블릿 이상 기준 |
| 다국어, 라이트/다크 자동 전환 | 한국어만, 색 규칙은 고정 |

## 4. 사이트 구조

```
음향 시스템 랩
├── 홈 (커리큘럼)                         /
├── 레슨                                  /lessons/<장>/<레슨>/
│   ├── 1장 기초 (5편)
│   ├── 2장 처리기 (5편, 편마다 위젯)
│   └── 3장 콘솔 (둘러보기·실습실 안내)  ──┐
├── 실습실                                  /lab/  ◀┘
│   ├── X32 스타일 콘솔                    /lab/x32/
│   └── dLive 스타일 콘솔                  /lab/dlive/
│       └── (콘솔 안) 미션 패널 · 자유 모드
└── 음원 출처                              /credits/

공개 전 프로덕션: '준비 중' 한 페이지만 연다
```

- 레슨 경로는 지금 구조(`/lessons/<id>/`)를 그대로 쓴다. 실습실과 출처 페이지 경로는 이 문서에서 정한 안이다.
- 큰 길은 순서형 코스다(1장 → 2장 → 3장). 증상으로 찾아 들어가는 색인은 만들지 않고, 그 대신 레슨 제목을 현장 상황 문장으로 짓는다.

## 6. 화면별 구성

도식은 배치 순서를 보여 주는 안이다. 픽셀 단위 디자인은 구현할 때 정한다.

### S01 홈

```
┌──────────────────────────────┐
│ 음향 시스템 랩(가칭)            │
│ "만지고 들으며 배우는 방송실 음향" │
├──────────────────────────────┤
│ 1장. 음향 기초                  │
│  · 레슨 제목(현장 상황 문장) ×5    │
│ 2장. 처리기 다루기              │
│  · 레슨 제목 ×5                 │
│ 3장. 디지털 믹서 실습            │
│  · 레슨 제목                     │
├──────────────────────────────┤
│ [실습실 바로 가기]               │
│ 음원 출처                        │
└──────────────────────────────┘
```

- 처음 온 사람이 1장 첫 레슨부터 시작하게 둔다.
- 실습실 바로 가기는 레슨을 건너뛰고 콘솔부터 만지려는 사람을 위한 입구다.

### S02 레슨

```
┌──────────────────────────────┐
│ 홈 › 2장                        │
│ 제목: "설교 목소리가 웅웅거릴 때"   │
│ 요약 한 줄                       │
├──────────────────────────────┤
│ 본문 (용어는 처음 나올 때 풀이)    │
│ ┌──────────────────────────┐ │
│ │ S03 처리기 위젯 (어두운 패널)  │ │
│ └──────────────────────────┘ │
│ 본문 "HPF를 120Hz까지 올려 보라"  │
├──────────────────────────────┤
│ ◀ 이전 레슨        다음 레슨 ▶   │
└──────────────────────────────┘
```

- 본문은 밝은 바탕이다. 위젯만 어두운 장비 패널이다.
- 3장 레슨에는 위젯 대신 실습실 링크를 둔다.

### S03 처리기 위젯 (공통 틀)

```
┌ 처리기 이름 ─────────── [바이패스] ┐
│ 음원: [보컬 ▾]   [▶ 재생 / ■ 정지]  │
├──────────────────────────────┤
│  그래프 영역                       │
│  (응답 곡선 / 전달 곡선 / RTA)      │
├──────────────────────────────┤
│  노브·슬라이더 영역                 │
│  ◯ ◯ ◯ ◯        ▮ 미터 / GR 미터  │
└──────────────────────────────┘
```

| 위젯 | 그래프 | 조작 | 미터 | 기본 음원(안) |
|---|---|---|---|---|
| 프리엠프 | 없음 | 게인, HPF 켜기·주파수 | 입력 레벨 + 클리핑 표시 | 보컬 |
| PEQ+HPF | 주파수 응답 곡선 | 밴드 4개(로우셸프, 피킹 2, 하이셸프): 주파수·게인·Q, HPF | 출력 레벨 | 설교 |
| GEQ | 합성 응답 곡선 + RTA | 31밴드 슬라이더, 하울링 데모 시작 | RTA | 보컬 + 모니터 |
| 컴프레서 | 전달 곡선 | 스레숄드, 레이시오, 니, 어택, 릴리스, 메이크업, 검출 Peak/RMS | 입력·출력 레벨, GR | 보컬 |
| 게이트 | 없음(열림/닫힘 표시) | 스레숄드, 레인지, 어택, 홀드, 릴리스 | 입력 레벨, GR | 드럼 |

- 바이패스 버튼으로 처리 전후를 번갈아 듣는다.
- 휴대폰에서는 노브·슬라이더를 손가락으로 끈다. GEQ 31밴드는 패널 안에서만 가로로 스크롤한다.
- 처음 재생하기 전에 S08 볼륨 안내가 뜬다.

```
│ └────────────┘ └────────────┘ │
│ ※ 가로 태블릿 이상에서 열어 주세요  │

```

### S05 콘솔

두 기종은 같은 소리 엔진과 미션을 쓰고 화면 배치, 메뉴 흐름, 파라미터 범위와 표시 단위만 다르다.

```
┌ 상단 바 ─────────────────────────────────────────────┐
│ [▶/■ 재생] 기종 이름 [듣기: 메인/Aux1/Aux2] [미션 ▾ / 자유 모드] [처음 상태로] │
├──────────────┬──────────────────────────────────────┤
│ 화면 전환 탭   │  선택한 화면                            │
│ · 채널 스트립  │  (채널 스트립: 프리엠프→게이트→PEQ→컴프)    │
│ · Aux 모니터   │  (Aux 1·2: 채널별 센드, GEQ + RTA)        │
│ · 라우팅/패치  │  (패치: 입력 → 채널 연결표)               │
│ · 메인         │  (메인: 메인 L/R, 메인 GEQ + RTA)         │
├──────────────┴──────────────────────────────────────┤
│ 페이더 뱅크: CH1 … CH16                                │ 메인 │
│ (선택·뮤트·팬·메인 할당·미터·페이더)                     │      │
└──────────────────────────────────────────────────────┘
          ▲ 미션 진행 중에는 오른쪽에 S06 미션 패널이 붙는다
```

| 화면 | 할 수 있는 것 |
|---|---|
| 채널 스트립 | 선택한 채널의 프리엠프(게인, HPF) → 게이트 → PEQ → 컴프 → 페이더 순서대로 조절. 프리엠프 구역에 입력 미터(게인 뒤, 클리핑 표시)가 있다 |
| 페이더 뱅크 | 채널 16개의 선택, 뮤트, 팬, 메인 할당(켜짐/꺼짐), 미터(페이더 뒤 레벨), 페이더. 메인 페이더 |
| Aux(모니터 믹스) | Aux 2개(Aux 1 보컬 모니터, Aux 2 밴드 모니터). 채널별 센드 양, pre/post 선택, Aux 출력 페이더, Aux별 GEQ 31밴드와 RTA |
| 라우팅/패치 | 입력(무대 박스 단자) → 채널 연결 바꾸기. 빈 입력도 보인다 |
| 메인 | 메인 L/R 레벨, 메인 GEQ 31밴드와 RTA |

- 채널 슬롯은 16개다. 음원은 약 13개라서 나머지 슬롯은 빈 입력이다.
- RTA는 그 버스 출력의 주파수별 크기를 막대로 보여 준다. 하울링 주파수는 RTA에서 튀어나온 막대로 찾는다.
- 상단 바의 '듣기'로 이어폰에 나갈 소리를 메인, Aux 1, Aux 2 중에서 고른다. 실제 콘솔에서 헤드폰으로 모니터 믹스를 확인하는 것과 같다. 하울링은 무대 전체에서 들리는 소리라서 듣기 선택과 상관없이 들린다.
- 기종별 화면 배치는 각 기종 매뉴얼을 확인한 뒤 정한다(확인 필요). 확인한 매뉴얼과 날짜는 해당 기종 파일 주석에 남긴다.
- 기기명은 "X32 스타일", "dLive 스타일"로만 쓰고, 제조사 로고나 스크린샷은 쓰지 않는다.

### S06 미션 패널

```
┌ 미션 ────────────────────┐
│ [하울링 잡기 ▾]             │
│ 상황 설명                   │
│ "찬양 중 보컬 모니터에서      │
│  '삐-' 소리가 납니다"        │
├────────────────────────┤
│ 상태: 진행 중 / ✔ 성공       │
│ [힌트 1] [힌트 2] [힌트 3]   │  ← 누를 때마다 하나씩 열림
│ [처음 상태로 다시]           │
├────────────────────────┤
│ (성공 뒤) 해설: 왜 이게 답인가 │
│ [다음 미션 ▶]               │
└────────────────────────┘
```

- 미션을 고르면 문제가 있는 믹서 상태로 바뀐다.
- 조작하는 동안 실시간으로 판정한다. 성공하면 바로 표시한다.
- 완료 기록은 남기지 않는다. 새로고침하면 처음부터다.

### S07 화면 크기 안내

- 콘솔 화면(S05)을 가로 너비 1024px보다 좁게 열면 콘솔 대신 이 안내를 보여 준다(기준 값은 안).
- 문구 예: "콘솔 실습은 가로로 놓은 태블릿이나 컴퓨터에서 열어 주세요."
- 홈과 레슨으로 돌아가는 링크를 둔다.

### S08 볼륨 안내

- 페이지를 열 때마다, 그 페이지에서 처음 재생하기 전에 한 번 띄운다(저장하지 않는다).
- 문구 예: "이어폰·스피커 볼륨을 낮춘 뒤 시작하세요. 하울링 실습에서는 소리가 커질 수 있습니다."
- 엔진에는 안전 리미터가 있고, 하울링 소리 크기에도 상한이 있다.

### S09 음원 출처

- 음원마다 곡명, 만든 사람, 출처 링크, 라이선스(CC BY 3.0 등)를 표로 적는다.
- 직접 녹음한 설교 음원도 적는다.

### S10 준비 중

- 공개 전까지 프로덕션 주소(sound-system-lab.vercel.app)에 이 페이지만 둔다.
- 작업 확인은 프리뷰 배포로 한다.

## 7. 사용자 흐름

### 처음 온 봉사자

```
홈(S01) → 1장 첫 레슨(S02) → … → 2장 레슨 + 위젯(S03)
   → 3장 레슨 → 실습실 입구(S04) → 기종 선택 → 콘솔(S05)
   → 미션 선택(S06) → 힌트 → 성공 → 해설 → 다음 미션
```

### 문제부터 해결하고 싶은 봉사자

```
홈(S01)에서 현장 상황 제목을 훑어봄
   → "예배 중 '삐-' 하울링이 날 때" 레슨(S02) → GEQ 위젯에서 하울링 데모
   → 실습실에서 하울링 잡기 미션
```

### 콘솔부터 만져 보고 싶은 봉사자

```
홈(S01) → [실습실 바로 가기] → 기종 선택 → 콘솔(S05) 자유 모드
```

### 위젯 한 번 쓰기

```
[▶ 재생] → (처음이면) 볼륨 안내(S08) → 음원 재생
   → 노브 돌리기 → 소리·그래프가 바로 바뀜 → [바이패스]로 전후 비교
```

## 8. 미션 명세

| 미션 | 상황(시작 상태) | 해결 방향 | 성공 조건 | 함정(실패 처리) |
|---|---|---|---|---|
| 하울링 잡기 | 보컬 모니터(Aux 1)의 특정 대역에서 하울링이 점점 커진다 | Aux 1 RTA로 주파수를 찾고 Aux 1 GEQ나 채널 EQ로 그 대역을 깎는다 | 그 주파수의 하울링이 멈추고, 보컬이 모니터에서 들리는 크기는 기준 이상으로 유지 | 센드·Aux 페이더·채널 페이더를 내리거나, 채널을 뮤트하거나, GEQ를 통째로 내려서 소리를 줄이면 성공으로 치지 않는다 |
| 설교 또렷하게 | 설교 채널이 웅웅거리고 크기가 들쭉날쭉하다 | HPF를 켜고, 저중역을 조금 깎고, 컴프를 가볍게 건다 | HPF 주파수, 저중역 감쇠량, 컴프 레이시오·GR이 각각 지정 범위(하한과 상한) 안 | 과하게 깎거나 눌러서 범위를 벗어나면 미완료 |
| 게인 맞추기 | 몇 채널은 클리핑, 몇 채널은 너무 작다 | 페이더가 아니라 프리엠프 게인으로 맞춘다 | 해당 채널들의 입력 피크(프리엠프 입력 미터 기준)가 목표 범위 안 | 페이더만 움직이면 입력 레벨이 그대로라 미완료 |
| 소리 안 나는 채널 | 패치, 뮤트, 페이더, 메인 할당 중 몇 곳이 잘못되어 있다 | 신호 흐름을 따라가며 끊긴 곳을 찾는다 | 지정 채널의 소리가 메인까지 나온다 | 없음 |

- 미션마다 힌트는 2~3단계다. 처음에는 방향만 알려 주고("어느 화면을 봐야 할까?"), 갈수록 구체적으로 알려 준다("Aux 1의 GEQ에서 2.5kHz 근처").
- 성공하면 "왜 이게 답인가" 해설을 보여 준다. 해설에서 판정 기준 수치의 근거도 설명한다.
- 두 기종 모두에서 같은 미션을 풀 수 있어야 한다.
- 미션은 데이터(시작 상태, 판정, 힌트, 해설)로만 추가할 수 있게 만든다.
